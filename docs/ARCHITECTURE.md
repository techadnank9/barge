# Architecture

## System shape

Two Python voice services and one Next.js dashboard, joined by Supabase.

```
   Caller (phone)                         VoiceOS (desktop, voice)
        |                                        |
        v                                        v
  a1mobile telephony                     Custom MCP connector
   (TeXML webhook)                        (fastmcp, HTTP /mcp/)
        |                                        |
        v                                        v
  Phone service (Flask) ------.      .---- MCP service (fastmcp)
        |                      \    /            |
   real SMS out                \  /       tools: get_chord_chart,
   (a1mobile /api/sms)          \/        log_practice, schedule_practice
        |                    Supabase             |
        |            (practice_entries table)     |
        '------------------> insert <-------------'
                               |
                               | realtime subscription
                               v
                     Next.js dashboard (judges watch)
                     row appears live on insert
```

## Components

### 1. Coaching brain (shared, Python) — `songs.py`
Pure logic, no I/O beyond the optional LLM call. `get_chart(name)` returns a
chord chart and a source (`seed` or `generated`). Five hand-verified seed songs;
anything else is generated by the LLM with a `confident` flag so the agent can
stay honest about chords it isn't sure of. Both services import this. Do not
fork it.

### 2. Phone service (Python, Flask)
Answers a1mobile calls with TeXML. Walkie-talkie turns:
`/voice → /handle-song → /handle-turn (loops) → /finish`. On finish it sends a
real SMS via a1mobile and inserts a practice entry into Supabase. Returns
`application/xml` (required or the call drops). Reference:
`reference-python/phone_server.py`.

### 3. MCP service (Python, fastmcp)
A custom VoiceOS connector serving four tools over streamable HTTP at `/mcp/`.
`log_practice` and `schedule_practice` insert into Supabase; `get_chord_chart`
reads the coaching brain; `recent_practices` reads back. VoiceOS confirms before
it acts, so a spoken "log my practice" shows a confirm card, then the tool
fires. Reference: `reference-python/mcp_connector.py`.

### 4. Persistence (Supabase)
One table, `practice_entries`, that both services write to and the dashboard
reads. Supabase realtime pushes inserts to the dashboard with no polling. Schema
in `supabase/schema.sql`.

### 5. Dashboard (Next.js App Router + Supabase)
Subscribes to `practice_entries` inserts and renders each new row live, tagged by
source (`phone` or `voiceos`) with the song and hard spots. This is the surface
judges watch during the VoiceOS demo; the live row is the confirmable side
effect.

## Why this split
- The two voice surfaces are the scoring parts and already have tested Python.
  Rewriting the MCP server in TypeScript trades proven code for risk on a clock.
- The dashboard benefits from Next.js + Supabase realtime — a polished, live UI
  is where judges look and where "this feels built" points come from.
- Supabase is the seam: neither service blocks the other, and both feed one
  visible log.

## Data flow: a phone session
1. Caller dials the a1mobile number → `/voice` greets, asks for a song.
2. `/handle-song` resolves the chart (seed or generated) → coaches.
3. `/handle-turn` loops the coached practice, captures hard spots.
4. `/finish` sends the SMS. On 200: insert a `practice_entries` row (source
   `phone`) and say "texted you." On failure: say "nothing was sent."
5. The insert pushes to the dashboard live.

## Data flow: a VoiceOS session
1. User speaks "log my Wonderwall practice, struggled with the Em7 to G change."
2. VoiceOS shows a confirm card → user approves.
3. `log_practice` inserts a `practice_entries` row (source `voiceos`).
4. The insert pushes to the dashboard live.

## Deployment for the demo
- Python services run locally (or on a small host); phone webhook exposed via
  ngrok, MCP connector added to VoiceOS by URL (`http://localhost:8000/mcp/`).
- Next.js dashboard runs locally (`npm run dev`) on the shared screen, pointed
  at the Supabase project.
- Supabase is hosted (free tier is fine).
